# Integration contract (2026-10-22)

Product: TypePro 1.6.0 source. Tauri 2 + React + Vditor. Mac arm64; Android minSdk 26, arm64 and ARMv7 when practical. Local-first; optional GitHub synchronization uses GitHub's device authorization, with no TypePro identity service. The public plugin market is independent of note synchronization and requires no login. Shared TypeScript models: src/lib/types.ts, camelCase JSON. This revision describes source contracts; it does not claim a 1.6.0 binary build, plugin publication or runtime acceptance.

Native commands (camelCase JS arguments; Rust snake_case params):

- load_workspace() -> Workspace (empty initially; no seeded personal notes).
- save_workspace({workspace: Workspace}) -> void. Serialize writes, validate UUID ids, write Markdown files and atomic index, do not erase data on parse/I/O failure. Each document is notebooks/<notebookId>/<documentId>.md. Plugins can be in separate local records. Root frontend serializes saves.
- import_bundle({name:string, bytes:number[], notebookId:string|null}) -> Workspace. Accept .md/.markdown or our portable ZIP. Import into indicated notebook for .md, create an Imported notebook when absent. ZIP preserves notebook grouping. New ids and duplicate names preserve both existing/imported data. Filesystem paths and zip bomb limits must be checked. Save merged state, return it.
- export_bundle({notebookId:string|null, documentId:string|null}) -> {name:string,bytes:number[]}. Whole workspace/all notebooks, one notebook, or one document ZIP. Archive contains ordinary Markdown + assets + manifest. All local attachments must survive import.
- export_markdown({notebookId:string,documentId:string}) -> {name,bytes}. Plain markdown only; UI labels attachments belong in ZIP.
- save_asset({name:string,bytes:number[]}) -> {path:string,url:string}. Canonical Markdown asset reference ../../assets/<uuid>.<extension>. url is a data URI for editor rendering. Local assets stored in assets/ relative to workspace root.
- resolve_asset({path:string}) -> string data URI. Only canonical ../../assets references accepted; no arbitrary filesystem read.
- get_storage_path() -> string for desktop diagnostics.
- get_notebook_location({notebookId:string}) -> {path:string,custom:boolean}. Mac only; root includes notebooks/<id>/ and assets/.
- set_notebook_location({notebookId:string,path:string|null}) -> same. Mac only; null restores default root. Require an existing empty or same-notebook-owned folder. Stage documents/assets before committing local locations.json; preserve source files and destination backups. Paths never enter Workspace/ZIP. Mobile rejects both location commands.
- write_transfer_uri({uri:string,bytes:number[]}) -> void. Android-only content:// destination granted by system Save picker; native ContentResolver closes OutputStream after writing to avoid plugin-fs detachFd metadata/empty-file issue. Desktop keeps official writeFile.
- get_transfer_name({uri:string}) -> string. Android-only content:// source granted by system picker; query OpenableColumns.DISPLAY_NAME to retain filename. ZIP detection must also inspect magic bytes.

Native storage implementation must not require arbitrary frontend filesystem privileges. UI import/export uses official dialog + filesystem plugins (supports Android content URIs). These plugins need read-file/write-file permissions, paths selected by the system dialog only. External links use opener with explicit http/https filter. Native command access restricted to main app window.

`Workspace = {version:1,notebooks:Notebook[],plugins:InstalledPlugin[],extensions?:ExtensionState}`. `InstalledPlugin` retains device-local `{manifest,code,files?,enabled,market?}`; `market` is `{sha256,size,downloadUrl}`. `manifest.apiVersion` accepts `1|2|3`. Optional `extensions` is saved in the local index and omitted by note ZIP export; importing notes does not replace or clear existing extension state.

`ExtensionState = {entries:ExtensionEntry[],installs:PluginInstallation[]}`:

```ts
type ExtensionEntry = {
  pluginId: string; key: string; value: JsonValue;
  updatedAt: string; deviceId: string; deleted?: boolean;
};
type PluginInstallation = {
  id: string; manifest: InstalledPlugin['manifest']; source: 'market' | 'local';
  code?: string; files?: Record<string,string>; sha256?: string; size?: number; downloadUrl?: string;
  updatedAt: string; deviceId: string; deleted?: boolean;
};
```

Market installation records pin SHA-256, byte size and a Release URL, with no code; local records contain code/resources and no market fields. Deletion retains a tombstone (deleted entry values are `null`; deleted local installation code is empty). Enabled state and permission decisions are never installation-record fields. `JsonValue` accepts only finite JSON values with depth <=64 and no `__proto__`, `prototype` or `constructor` object fields. Keys match `[A-Za-z0-9][A-Za-z0-9._-]{0,127}`, excluding those reserved values. Limits across all plugins: 32 MiB serialized extension state, 20000 data entries, 128 installation records including tombstones; local imported code <=512 KiB.

`mergeExtensions(base,local,remote)` merges entries by `(pluginId,key)` and installs by id. Absence is not deletion. Independent records survive; conflicting changed records choose later `updatedAt`, then lexicographically greater `deviceId`, then normalized serialized content as a deterministic tie-break. Explicit deletion markers propagate removals. Plugin data namespaces prevent one plugin reading another plugin's storage.

Plugin market native commands (main window only; `src-tauri/src/plugin_market.rs`, frontend validation in `src/plugins/market.ts`):

- `plugin_market_catalog()` -> `{schemaVersion:1,updatedAt:string,plugins:MarketPlugin[]}`. Fetch only `https://raw.githubusercontent.com/Proberen/typepro-plugins/main/catalog-v3.json` without GitHub authorization. The catalog is at most 1 MiB and 500 unique plugin ids; `updatedAt` is an RFC 3339 timestamp with at most 40 characters. Legacy `catalog.json` remains API-1-only for 1.4.x clients.
- `plugin_market_download({id:string,version:string,sha256:string})` -> `number[]`. Re-read the fixed catalog and require the id, version and SHA-256 to match the metadata the user reviewed. Start only at `https://github.com/Proberen/typepro-plugins/releases/download/<tag>/<filename>.zip`, then allow at most three redirects to supported GitHub Release asset origins. Verify the exact catalog size and SHA-256 before returning bytes; package size is at most 8 MiB. The frontend parses the ZIP with the existing installer and requires the packaged manifest identity, name, version, description, API version and permission set to match the reviewed catalog.
- `plugin_market_restore({entry:MarketPlugin})` -> `number[]`. Restore a synchronized immutable pin without requiring it to remain in the latest catalog. Validate all entry fields and require exactly `https://github.com/Proberen/typepro-plugins/releases/download/plugin-<sha256(id+'@'+version)>/<id>.zip`, then use the same allowed redirects, size and SHA-256 checks. The frontend again validates the ZIP Manifest against the supplied entry. This does not authorize execution.

`MarketPlugin` contains manifest fields `{id,name,version,description?,apiVersion:1|2|3,permissions:string[],networkOrigins?:string[]}` plus `{downloadUrl:string,sha256:string,size:number}`. API 1 permissions remain `commands`, `panels`, `editor.insert`, `notes.read`, `notes.write`; API 2 additionally allows `storage`, `home.activity`, `assistant`. API 1 cannot declare new permissions, and unknown API versions/permissions are rejected. SHA-256 is 64 lowercase hexadecimal characters; size is a positive integer in bytes. Market versions are strict SemVer without build metadata, at most 40 characters; numeric identifiers reject leading zeros and prerelease identifiers cannot be empty. Local-import version validation is unchanged. Versions that cannot be strictly ordered are excluded from market update offers, and manual market updates never downgrade.

The market fetches on entry/manual refresh and every 60 seconds only while its page is open and visible; requests do not overlap. Hiding or leaving the page stops polling. No browser-preview network bypass is supplied: installation requires the native Mac or Android app. Catalog/network failures do not disable or remove installed plugins. The market uses only the independent public repository, never private notes or note-sync credentials.

Install/update requires review of the pinned catalog item. New plugins are disabled; a manual update preserves the previous enabled state only when it adds no permission or network origin, otherwise it remains disabled until explicit permission approval. Read the latest installed list after download, reject a changed slot/version, and persist the replacement before publishing it to the plugin host. A failed download/validation/save keeps the old plugin. Local ZIP/JSON import remains available and rejects an existing id until the user removes it.

`restoreSyncedPlugins({getWorkspace,apply,isCancelled?,download?,onError?})` restores `extensions.installs` without executing code. Market records download their exact pin; local records validate synced Manifest/code/resources. First restore and changed code/resources/version/permissions/origins are disabled; identical existing Manifest/code/resources keep that device's enabled choice. Tombstones remove local installation while retaining data. Records absent from the installation list do not remove unmigrated local plugins. Maximum live installs remains 24; download failures preserve the previous plugin. Re-read the latest record and installed slot after awaits and before applying; stale/cancelled work is discarded, unrelated local edits are rebased. Applying restoration does not create a new installation change. Neither note ZIPs nor sync records carry local enabled/permission choices; local-import code/resources do enter the private sync record. Publication details are in `docs/MARKET.md` and `docs/PLUGINS.md`.

The publisher validates/package-checks all plugins, keeps same-version artifacts immutable, and updates version-compatible `catalog.json`, `catalog-v2.json` and `catalog-v3.json` in one final commit after every package succeeds. Historical checks prefer existing `catalog-v3.json`, then `catalog-v2.json`, then `catalog.json`; a present malformed catalog is an error.

Plugin SDK and native services use the single normative [API 3 contract](PLUGIN-SPEC.md). `src/plugins/` and `public/plugins/` implement generic Worker/view isolation, permission checks, events, commands, synchronized JSON, trusted dialogs, file selection and domain-scoped HTTPS/credential access. No feature-specific activity/assistant code is linked into the application. Plugin implementations live exclusively in the independent plugin repository.

Generic native commands (`src-tauri/src/plugin_services.rs`, trusted main window only): `plugin_session_start`, `plugin_session_stop`, `plugin_network_request`, `plugin_network_cancel`, `plugin_secret_configure`, `plugin_secret_status`, `plugin_secret_remove`. Transport returns raw UTF-8, not provider-specific messages. The shell creates opaque runtime sessions and passes only approved exact HTTPS origins. Plugin frames cannot invoke Tauri. Credentials are plugin-scoped and device-local in Keychain/Keystore (`PluginSecretsPlugin.kt`). The trusted host input never returns a secret to a plugin. Previous AI credentials require one-time reconfiguration.

GitHub native commands (JS camelCase arguments; implementation in `src-tauri/src/github/`, client bridge in `src/sync/native.ts`):

- `github_status()` -> GithubStatus: public App configuration, connected/account/repository state, device identity/name, intervalMinutes, lastSyncedAt and lastSource. Never returns access/refresh credentials.
- `github_configure({clientId,appSlug,intervalMinutes,deviceName})` -> GithubStatus. Interval is integer 0..1440 minutes; 0 disables periodic synchronization. Changing App identity clears current authorization/connection state; other devices keep their own configuration.
- `github_start_authorization()` -> `{userCode,verificationUri,expiresIn,interval}`. Native-only device code stays in memory. User-visible verificationUri must be exactly `https://github.com/login/device`.
- `github_poll_authorization()` -> `{status,interval,state}`. Status is pending/slow_down/expired/denied/authorized; state contains public GithubStatus only after success. Poll at the server's interval, honoring slow_down and expiry.
- `github_cancel_authorization()` -> void. Invalidate the in-memory flow; do not persist cancelled credentials.
- `github_prepare_repository()` -> `{status,installationUrl,state}`. Status is ready/installation_required. Only current-account private, unarchived `typepro-notes` is supported. Attempt creation if absent; check repository ID, default branch and selected-repository App installation. Only that one repository may be selected. Installation URL is the configured public GitHub App installation page.
- `github_read_remote()` -> `{head,base,remote}`. Head is Git commit SHA; base and remote are SyncSnapshot or null. Read a coherent commit/tree/manifest, verify blob identities/paths and required assets, import assets through Storage preflight, then return the wire snapshot. Null remote means no TypePro manifest, not permission to delete local notes. Network awaits must not hold the Storage mutex.
- `github_publish({expectedHead,workspace:SyncWorkspace})` -> `{head,snapshot}`. Export current parameter Markdown plus referenced assets from Storage; validate the same snapshot against those bytes. Create only changed Git blobs/tree/commit, then advance the default branch with `force:false`. Return `REMOTE_CHANGED:` on concurrent change; never force overwrite. Identical metadata/assets produce no new commit. Remove only paths owned by the previous TypePro manifest; unrelated repository files survive.
- `github_checkpoint({head,snapshot})` -> void. After local merged state is durably saved, store exactly the accepted remote snapshot as the next merge baseline. Never checkpoint a newer unpublished local draft. Update public sync time/source separately from document updatedAt.
- `github_disconnect()` -> GithubStatus. Remove local credentials and connection state, retaining local notes, cached content, remote repository and Git history. Does not delete a GitHub account or automatically uninstall/revoke the App on GitHub.

`SyncWorkspace = {version:1,notebooks:Notebook[],extensions?:ExtensionState}`. `SyncSnapshot = {format:'typepro-github',version:1,notebooks:Notebook[],extensions?:ExtensionState,source:{deviceId,name,platform},syncedAt}`. Sync models strictly reject unknown fields, unsupported versions, duplicate/global UUIDs, invalid covers, oversized records and invalid source/sync timestamps. `toSyncWorkspace` explicitly extracts these allowed fields, excluding local `plugins`. Plugin installation records/data cross devices through `extensions`; enabled/permission choices, absolute directory mappings, themes/folds/UI settings and AI/GitHub credentials remain local.

Remote layout is `.typepro/manifest.json`, optional `.typepro/extensions.json`, `notebooks/<bookUUID>/<docUUID>.md`, and `assets/<assetUUID>.<extension>`. The manifest contains notebook/document order and metadata plus blob SHA-1 references, source and syncedAt; optional `extensions` is the blob SHA-1 of the separate extension JSON. Ordinary UTF-8 Markdown lives in its own files. Canonical Markdown/cover asset references remain unchanged. Managed files must be plain regular Git blobs (`100644`), not symlinks/executables. Limits: 1000 notebooks, 5000 documents, 16 MiB/document, 32 MiB/asset, 32 MiB extension JSON, 256 MiB managed content including extension file/manifest, 10000 files including manifest, manifest <=8 MiB. No LFS. Missing or inconsistent referenced content stops synchronization before local notebook state is replaced.

Remote format/version remain `typepro-github`/`1`. TypePro 1.5.0 reads old manifests without extensions; 1.4.x strictly rejects the new `extensions` manifest field. Upgrade every syncing device to 1.5.0 before publishing plugin extension data. Do not describe this optional-field addition as backward-readable by old clients.

`mergeWorkspaces(base,local,remote)` is asynchronous and accepts SyncWorkspace values, not wire SyncSnapshot; convert non-null snapshots with `toSyncWorkspace` first. Merge documents globally by UUID, recognizing cross-notebook moves. Independent field/document changes merge; concurrent unequal document fields preserve local original ID and a deterministic remote conflict copy. Delete-vs-unchanged deletes; timestamp-only changes do not prevent deletion. Delete-vs-edit preserves changed content in a named deletion-conflict copy and recovers its container if needed. Concurrent notebook name/cover conflicts prefer local fields and count a conflict without duplicating all documents. Retries reuse conflict UUIDs, preserve edited copies, and avoid equivalent copies introduced by concurrent publication. No line-level Markdown merge is promised.

Frontend synchronization first collects and saves edits, reads/merges/publishes, then merges the accepted result again against the latest local state with a reference-based compare-and-swap; typing during network activity must survive. Persist before checkpointing. Remote-change retry is bounded to three attempts. Default interval is 5 minutes while foreground/online; startup/foreground/online events trigger checks when interval >0. Interval 0 is manual-only. Background suspension, sleep, exit and force-quit have no scheduling guarantee.

Public defaults are Client ID `Iv23lipNCmyApIdzUDhY` and App slug `typepro-proberen` (private App TypePro-Proberen, only GitHub account Proberen). Other accounts need their own App/configuration; built-in configuration is not a multi-user public service. Required App permissions: Contents read/write, Metadata read-only, Account Repository creation read/write, Device flow enabled; select only the dedicated repository for installation. Private key/client secret are never embedded in the client. Native credentials use macOS Keychain or Android Keystore-protected AES-GCM storage; no token is returned to JavaScript/plugins, included in ZIP/sync data or written to browser storage. Native HTTP targets fixed GitHub HTTPS origins and refuses redirects. Rate limiting/auth expiry/I/O errors surface without discarding local notes. Repository privacy is not end-to-end encryption.

Storage synchronization helpers are `export_sync_files(&Workspace)->Result<Vec<SyncFile>,String>` and `import_sync_assets(&[SyncFile])->Result<(),String>`, with `SyncFile {path:String,bytes:Vec<u8>}` and `pub(crate) validate(&Workspace)`. File export uses supplied Markdown and canonical referenced assets, including custom directory sources, excluding local metadata/installed-code records; the repository layer writes extension JSON separately from snapshot.extensions. Import accepts only `assets/<UUID>.<ext>`, preflights the complete batch and all mapped directory copies, enforces storage limits and symlink/path checks, rejects same-name/different-byte content, and publishes new global assets atomically without replacing existing files. A later workspace save copies referenced assets to custom notebook roots.

Editor module src/editor/MarkdownEditor.tsx:
default export component, props {documentId:string, markdown:string, mode:EditorMode, onChange:(markdown:string,edit?:{beforePlain:string,afterPlain:string,history?:'undo'|'redo'})=>void, trackEdits?:boolean, onReady?:(api:EditorHandle)=>void, onError?:(error:string)=>void, saveAsset:(file:File)=>Promise<{path:string,url:string}>, resolveAsset:(path:string)=>Promise<string>}. `trackEdits` enables a plain-text projection only while document-change subscribers need it; events expose host-assigned human/plugin/sync/import provenance without interpreting plugin business rules. EditorHandle {insertText(text:string):void; focus():void; getValue():string; getSelection():string; executeCommand(id:string):void; getHeadings():EditorHeading[]; scrollToHeading(id:string):void}. EditorHeading is {id:string,text:string,level:number}; optional onHeadingsChange and light/dark theme props keep the in-document nested outline and code theme in sync. Export type. Main UI manages mode and current doc. Must flush current edits before switching doc/mode. Root remounts with key=documentId only, not every edit. Include editor.css. All Vditor assets local; CommonMark/GFM/math/Mermaid/footnotes/TOC/front matter/HTML with XSS sanitization. Do not rewrite source on initial load or solely switching modes. Persisted Markdown remains source of truth. Relative image display must never replace markdown URLs with data URLs. Only edit/read modes remain. Fixed toolbar renders only in edit mode. Optional documentTools: ReactNode supplies the body outline toggle. Optional documentOutline: ReactNode is the first child of editor-body-flex, beside editor-surface; the desktop outline is a permanent left column while open, mobile uses a left drawer. Heading navigation and body clicks do not close it. Selected-text fonts/colors use safe inline HTML. Tables insert at caret with requested rows/columns including one header row. Code folds are machine-local, outside Markdown. src/flow exports FlowDesigner and renderFlowPreview(container, source); unsupported Mermaid is kept losslessly in Mermaid mode. Reading view is non-editable.

Plugins module src/plugins/: generic isolated API 3 host with capability-checked operations and extensible slots; see [Plugin API 3](PLUGIN-SPEC.md) and [developer guide](PLUGINS.md). Root renders registered surfaces and command actions without feature-specific imports. API 1 remains supported; API 2 feature registrations are retired with an update notice. Installation data/resources and synchronized plugin JSON retain their existing namespaces.

Source workspace: work/notebook. Outputs contain user deliverables, not private notes, credentials, signing keys or build caches. Application and public-plugin publication are separate operations; source changes do not imply either has completed.

Notebook.cover is optional: `preset:0` through `preset:5`, or the same canonical asset reference used by local images. Missing cover remains valid for old data. ZIP export includes custom cover assets, deduplicates shared references, and import remaps cover and Markdown paths together. Android upgrades preserve the original package and signing key; current versionCode is defined in the native build configuration.

Code blocks: canonical pre/code remains the Markdown source. An independent CodeMirror widget owns input, selections, history and composition; rendering enhancements must not rebuild active widgets on each key. Flush edits before mode/document navigation. `mountCodeEditor(host, options)` is shared with Mermaid source editing. `formatCode(language, code): Promise<string>` runs bundled engines in a module worker; Mermaid syntax validation reuses the existing local page runtime. Failures preserve input; formatting applies only while document and contents still match the request, as one undoable change. No external formatter service or per-device installation. Fold metadata stays local, outside Markdown.

Body blocks: `block-controls.ts` owns external handle/menu/drag overlays; `block-targets.ts` resolves canonical blocks, excluding widget preview internals. `block-actions.ts` moves real nodes, preserves list/task semantics and inserts a blank paragraph after deleting the last block. Edit only; heading moves alone; all operations are current-document only. `runIRTransaction` commits pending typing before one native undoable operation. Code widgets removed through controls are retained in a bounded 50-deletion cache and released with the document. Mobile uses a 280 ms long press on the handle.

Images: `image-resize.ts` owns the external four-corner proportional resize overlay; preview gestures never change canonical DOM. On commit, `persistImageWidth` records one native transaction and writes a width-bearing HTML image, retaining canonical relative attachment paths, alt/title and neighboring HTML. Width is capped by the containing body/table cell/list/quote. Source Markdown is unchanged until a completed resize. Runtime image previews/classes are stripped from snapshots and document history; standalone HTML images render as images in both editor and reader.

Android 同步附件使用 `renameat2(RENAME_NOREPLACE)` 系统调用原子发布暂存文件；应用沙箱禁止硬链接，不使用 `link`。通过系统调用避免依赖较新 Android API 的 Bionic 符号。桌面继续使用硬链接。两者均拒绝替换预检后出现的目标文件；失败时清理暂存文件，不推进同步基线。
