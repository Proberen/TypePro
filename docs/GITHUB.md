# GitHub 同步

TypePro 1.3.0 可将 Mac 与 Android 的笔记双向同步到 GitHub 私有仓库。默认仍在本机保存，不需要 TypePro 账号或自建服务。断网时继续编辑，恢复网络后同步。

## 首次连接

1. 从首页、编辑页侧栏或底部状态栏打开「GitHub 同步」，点击「连接 GitHub」。
2. TypePro 显示设备验证码，并打开 GitHub 授权页面。在浏览器中登录 GitHub，输入验证码并确认授权。TypePro 不接收 GitHub 密码。
3. 应用检查当前账号下的私有 `typepro-notes` 仓库；不存在时尝试创建。已有同名公开仓库、归档仓库或不匹配的仓库不会被当作笔记库继续写入。
4. 如提示「授权笔记仓库」，点击「前往授权」，在 GitHub 选择 **Only select repositories**，只选 `typepro-notes`。返回应用，点击「我已授权，检查连接」。
5. 连接后设置设备名称，核对仓库与同步状态。第二台设备使用同一 GitHub 账号，完成设备授权后连接同一个仓库。

当前内置配置是私有 GitHub App **TypePro-Proberen**，仅供 GitHub 账号 `Proberen` 使用。默认配置已写入应用，无需手工输入 Client ID。仓库为 `Proberen/typepro-notes`；安装授权仍通过 GitHub 页面明确确认。

| 配置项 | 当前值 |
| --- | --- |
| GitHub App slug | `typepro-proberen` |
| 公共 Client ID | `Iv23lipNCmyApIdzUDhY` |
| 笔记仓库名 | `typepro-notes` |

Client ID 是公开应用标识，不是访问令牌。其他 GitHub 账号不能直接使用这个私有 App；需要自行注册 GitHub App，并在「GitHub App 设置」填写自己的 Client ID 与 slug。

## 日常同步

- 自动同步默认每 **5 分钟**执行，限应用打开且处于前台时；启动、回到前台和网络恢复也会触发检查。
- 设置为「仅手动同步」后，不运行周期任务，通过「立即同步」执行。
- Android 后台、省电暂停、强退以及 Mac 退出或休眠时，不保证定时同步。重新打开应用后再同步。
- 每次先保存当前本地编辑，再读取远端、合并并发布。网络请求期间新增的输入会再次合并到最新本地状态，不用较早快照覆盖正在输入的内容。
- 内容没有变化时不创建重复 Git 提交；已缓存并通过校验的附件不重复下载，相同 Git blob 不重复上传。

「最近同步」表示同步状态记录，「更新源」为快照内的设备名称。文档的 `updatedAt` 与快照的 `syncedAt` 分开保存，不能用同步时间替代内容更新时间。

## 离线与冲突

同步通过稳定 UUID 识别笔记和文档，以两端上次共同快照做三方合并。首次连接没有共同快照时，按 UUID 合并两边内容；同名但不同 UUID 的笔记会分别保留。

| 两端操作 | 结果 |
| --- | --- |
| 修改不同文档 | 分别保留修改，自动整合 |
| 同一文档一边改正文、另一边改标题或移动笔记 | 不冲突的字段可合并 |
| 同一文档两边改同一字段，内容不同 | 当前本地版本保留原 UUID；远端版本保留为「内容冲突」副本 |
| 一边删除、另一边未改 | 同步删除；单独变化的更新时间不算正文修改 |
| 一边删除、另一边仍在修改 | 修改内容保留为「删除冲突」副本；必要时保留所属笔记 |
| 两边同时改笔记名称或封面 | 本地字段优先，并计入冲突；不会因此丢弃正文 |

正文冲突保留完整版本，不自动拼接两份 Markdown 的行。冲突副本使用确定性 UUID，重试不会不断追加同一份副本；用户后续修改过的副本会保留。远端在发布期间更新时，应用重新读取并合并，最多重试三轮，不强制覆盖 Git 历史。

ZIP 导入会产生新 UUID，因此导入内容在同步中作为新笔记保留。同步删除会更新仓库当前文件；Git 提交历史仍可能保留旧版本。

## 同步范围与文件

同步笔记分组、名称、文档标题与 Markdown、内容更新时间、封面、本地附件和更新源。插件代码及其授权、Mac 自定义目录的绝对路径、主题、折叠状态及其他界面设置不进入同步数据。外链图片只同步 Markdown 中的地址，不下载并转存远端图片。

```text
typepro-notes/
  .typepro/manifest.json
  notebooks/<notebook-uuid>/<document-uuid>.md
  assets/<asset-uuid>.<extension>
```

Markdown 是普通 UTF-8 文件。清单记录分组、顺序、元数据、文件路径与 Git blob 校验值；图片沿用 `../../assets/<uuid>.<extension>` 引用。上传只取正文和封面实际引用的本地附件，不上传本机目录或整个应用文件夹。远端中不属于上次 TypePro 清单的其他文件不会因同步被删除。

首版最多同步 1000 本笔记、5000 篇文档，单篇正文 16 MiB、单个附件 32 MiB；远端纳入同步的文件及清单合计最多 256 MiB、10000 个文件，清单最多 8 MiB。不使用 Git LFS。GitHub 的 API 限流、网络和账号策略也会影响同步。

不应只在 GitHub 网页添加一个未登记到清单的 Markdown 文件来创建笔记。远端受管理文件和清单必须一致；缺文件、损坏数据或校验不匹配时会停止同步，保留本地内容。

## 权限与凭据

GitHub App 需要启用 **Device flow**。仓库安装范围必须为 **Only select repositories**，且只选当前账号的 `typepro-notes`；应用会检查安装范围、仓库归属、私有状态和未归档状态。

| GitHub App 权限 | 用途 |
| --- | --- |
| Repository permissions → Contents: Read and write | 读取和提交 Markdown、清单与附件 |
| Repository permissions → Metadata: Read-only | 读取专用仓库与默认分支信息 |
| Account permissions → Repository creation: Read and write | 首次连接时创建专用私有仓库 |

仓库创建属于账户级权限；仓库内容访问通过安装时选定的单一笔记仓库限制。无需把 GitHub App private key 或 client secret 放入客户端，也无需填写个人访问令牌。

授权凭据仅由原生层使用。Mac 存入钥匙串；Android 用 Keystore 中的设备密钥进行 AES-GCM 加密后保存在应用私有存储。前端仅获取连接状态和设备验证码，不获取访问令牌；笔记仓库、ZIP、插件 API 和浏览器存储均不包含凭据。

原生请求只访问固定 GitHub HTTPS 服务，禁止重定向。凭据过期、被撤销或无法读取时，需要重新连接。GitHub 同步不是端到端加密：有权访问私库的 GitHub 账号及 GitHub 服务可读取正文和图片。

## 断开和异常

「断开连接」清除本机访问凭据与连接状态，保留本地笔记、远端仓库和 Git 历史，不删除 GitHub 账号，也不自动卸载 GitHub App。本机同步缓存可能仍保留已下载内容。若还要撤销站点授权或移除安装，在 GitHub 设置中单独操作。

| 提示或现象 | 处理 |
| --- | --- |
| 验证码过期或取消授权 | 重新点击「连接 GitHub」获取验证码 |
| 尚未授权笔记仓库 | 核对 App 安装时只选择 `typepro-notes`，返回应用检查连接 |
| 仓库不是私有、已归档、被重建或默认分支变化 | 在 GitHub 核对仓库状态，再重新检查连接 |
| GitHub 限流、超时或暂时不可用 | 本地继续编辑，稍后重试；过短间隔可能增加限流 |
| 附件缺失、同名附件内容不同或文件校验失败 | 停止本次同步，恢复对应文件后重试；不会覆盖已有附件 |
| Mac 自定义目录失联 | 恢复本机目录后重试，不会把旧目录副本当作新内容覆盖 |

本文件依据源码和共享接口核对使用流程。真实 GitHub 设备授权、首次推拉、Mac／Android 双向离线冲突及平台安全存储的实测结论，以本次交付记录为准；静态审查不代表这些场景已通过实际验收。
